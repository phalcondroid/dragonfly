# Internationalization (i18n)

Dragonfly's i18n system follows the same **adapter pattern** as network adapters
— a common interface with pluggable implementations. Built-in adapters handle
ARB and JSON files. Custom adapters can read translations from a REST API, CMS,
database, or any source.

---

## Quick start

Create a subclass of `DragonflyI18n` with the adapter of your choice:

```dart
import 'package:dragonfly/dragonfly.dart';
import 'package:flutter/widgets.dart';

class AppI18n extends DragonflyI18n {
  static const _adapter = DragonflyArbAdapter(
    path: 'assets/i18n',
    supportedLocales: [Locale('en'), Locale('es'), Locale('fr')],
  );

  const AppI18n()
      : super(adapter: _adapter, supportedLocales: _adapter.supportedLocales);

  // ── Typed accessors (add one per translation key) ───────────────────────
  static AppI18n of(BuildContext context) =>
      Localizations.of<AppI18n>(context, AppI18n)!;

  String get helloWorld => translate('helloWorld');
  String pageTitle(int page) =>
      translate('pageTitle', args: {'page': '$page'});
  String get saveButton => translate('saveButton');
}
```

Wire it in your `MaterialApp`:

```dart
MaterialApp(
  localizationsDelegates: const [
    AppI18n(),
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
  ],
  supportedLocales: const [
    Locale('en'),
    Locale('es'),
    Locale('fr'),
  ],
  home: const HomeScreen(),
);
```

Use it anywhere in the widget tree:

```dart
Text(AppI18n.of(context).helloWorld);
Text(AppI18n.of(context).pageTitle(5));
ElevatedButton(
  onPressed: () {},
  child: Text(AppI18n.of(context).saveButton),
);
```

## Built-in adapters

### `DragonflyArbAdapter` — ARB files

ARB (Application Resource Bundle) is Flutter's native translation format.
Files are JSON with ICU plural support and `@`-prefixed metadata.

```json
// assets/i18n/app_en.arb
{
  "helloWorld": "Hello World",
  "@helloWorld": { "description": "Greeting on the home page" },
  "pageTitle": "Page {page}",
  "@pageTitle": { "placeholders": { "page": { "type": "int" } } },
  "itemCount": "{count, plural, =0{No items} one{1 item} other{{count} items}}"
}
```

```dart
DragonflyArbAdapter(
  path: 'assets/i18n',
  supportedLocales: [Locale('en'), Locale('es')],
)
```

### `DragonflyJsonAdapter` — JSON key-value files

Simpler format — flat JSON object. No ICU plural support.

```json
// assets/i18n/en.json
{
  "helloWorld": "Hello World",
  "pageTitle": "Page {page}",
  "saveButton": "Save"
}
```

```dart
DragonflyJsonAdapter(
  path: 'assets/i18n',
  supportedLocales: [Locale('en'), Locale('es')],
)
```

## Custom adapters

Implement `DragonflyI18nAdapter` to read translations from any source.
This is the same extensibility pattern as network adapters.

### REST API adapter

```dart
class HttpI18nAdapter extends DragonflyI18nAdapter {
  HttpI18nAdapter({required this.baseUrl, required this.apiKey});
  final String baseUrl;
  final String apiKey;

  final _supported = {'en', 'es', 'fr', 'de'};

  @override
  bool supports(Locale locale) =>
      _supported.contains(locale.languageCode);

  @override
  Future<Map<String, String>> load(Locale locale) async {
    final uri = Uri.parse('$baseUrl/translations/${locale.languageCode}');
    final response = await http.get(uri, headers: {'Authorization': 'Bearer $apiKey'});
    final data = json.decode(response.body) as Map<String, dynamic>;
    return data.map((k, v) => MapEntry(k, v.toString()));
  }
}
```

### CMS adapter (Lokalise, Crowdin, etc.)

```dart
class LokaliseAdapter extends DragonflyI18nAdapter {
  LokaliseAdapter({required this.projectId, required this.apiKey});
  final String projectId;
  final String apiKey;

  @override
  bool supports(Locale locale) => true; // Lokalise supports all locales

  @override
  Future<Map<String, String>> load(Locale locale) async {
    final uri = Uri.parse(
      'https://api.lokalise.com/api2/projects/$projectId/translations/${locale.languageCode}',
    );
    final response = await http.get(uri, headers: {'X-Api-Token': apiKey});
    final body = json.decode(response.body) as Map<String, dynamic>;
    final keys = body['keys'] as List;
    return {for (final k in keys) k['key_name'] as String: k['translations'][0]['translation'] as String};
  }
}
```

### Usage in `DragonflyI18n` subclass

```dart
class AppI18n extends DragonflyI18n {
  static final _adapter = HttpI18nAdapter(
    baseUrl: 'https://api.example.com',
    apiKey: 'sk-xxx',
  );

  const AppI18n()
      : super(adapter: _adapter, supportedLocales: const [Locale('en')]);

  static AppI18n of(BuildContext context) =>
      Localizations.of<AppI18n>(context, AppI18n)!;

  String get helloWorld => translate('helloWorld');
}
```

## Validation messages and ACL

Dragonfly provides a `DragonflyValidationMessages` class that holds all
form validation error messages, submit button labels, and ACL access-denied
messages. Set it in your `DragonflyConfig` to localize all user-facing text:

```dart
class SpanishMessages extends DragonflyValidationMessages {
  const SpanishMessages();

  @override String get required => 'Este campo es obligatorio';
  @override String get invalidEmail => 'Formato de correo inválido';
  @override String get submitButtonLabel => 'Enviar';
  @override String get authenticationRequired => 'Autenticación requerida';
  @override String requiredRoles(List<String> roles) =>
      'Roles requeridos: ${roles.join(', ')}';
  // ... override all 40+ messages
}

class AppConfig extends DragonflyConfig {
  @override
  List<DragonflyAdapterConfig> get adapters => [...];

  @override
  DragonflyValidationMessages? get validationMessages =>
      const SpanishMessages();
}
```

`DragonflyApp.init()` automatically sets these messages on both
`Validators` (form validation errors) and `DragonflySessionManager`
(ACL access-denied reasons).

If `validationMessages` is null (default), English messages are used.

## Placeholder interpolation

Both built-in adapters support `{param}` interpolation:

```json
{ "greeting": "Hello {name}, you have {count} messages" }
```

```dart
// AppI18n.of(context).greeting(name: 'Rick', count: '5')
text.translate('greeting', args: {'name': 'Rick', 'count': '5'});
// → "Hello Rick, you have 5 messages"
```

## Locale resolution

`DragonflyI18n.isSupported(locale)` checks `languageCode` match. For example,
`Locale('es', 'MX')` matches a supported `Locale('es')` because they share
the same language code.

```dart
final i18n = AppI18n();
i18n.isSupported(Locale('es', 'MX')); // true if Locale('es') is in supportedLocales
i18n.isSupported(Locale('pt'));       // false
```

## Without code generation (manual)

The system works fully without `@I18n` or build_runner. Just subclass
`DragonflyI18n`, pick an adapter, and add typed accessors by hand:

```dart
class AppI18n extends DragonflyI18n {
  static final _adapter = DragonflyJsonAdapter(
    path: 'assets/i18n',
    supportedLocales: const [Locale('en'), Locale('es')],
  );

  const AppI18n()
      : super(adapter: _adapter, supportedLocales: _adapter.supportedLocales);

  static AppI18n of(BuildContext context) =>
      Localizations.of<AppI18n>(context, AppI18n)!;

  String get helloWorld => translate('helloWorld');
  String pageTitle(int page) =>
      translate('pageTitle', args: {'page': '$page'});
}
```

## With `@I18n` annotation (future: code generation)

The `@I18n` annotation exists in `dragonfly_annotations`. A future builder
phase will generate the typed subclass automatically from the adapter's
translation files:

```dart
@I18n(
  adapterType: 'DragonflyArbAdapter',
  path: 'assets/i18n',
  supportedLocales: ['en', 'es'],
)
class AppI18n extends _$AppI18n {
  const AppI18n();
}
```

The generator is planned for v0.2.0. Until then, subclass `DragonflyI18n`
manually (the generated code follows the same pattern).

## Architecture

```
DragonflyI18nAdapter          ← abstract contract
    │
    ├── DragonflyArbAdapter    ← built-in: ARB files
    ├── DragonflyJsonAdapter   ← built-in: JSON files
    └── CustomHttpAdapter      ← community: REST API, CMS, etc.

DragonflyI18n                 ← runtime base class
    │  extends LocalizationsDelegate
    │  provides translate(key, {args})
    │  integrates with Flutter's Localizations widget
    ▼
AppI18n                       ← app-specific subclass
       typed getters per key
       AppI18n.of(context)
```

The adapter system is identical to network adapters ([ADR 0002](../adr/0002-repository-parameter-binding.md)):
- Abstract interface → community publishes implementations
- Built-in adapters for common formats
- Custom adapters registered via the same pattern
- Transport-agnostic — screens never change when the translation source changes
